## 切帧与播放约定

[animation-manifest-v2.json](../assets/animation-manifest-v2.json) 为当前权威切帧索引。读取 `characters[].clips.{动作}.frames[]`，按实际 `frame_count` 播放；`comparison_runs` 中是六人旧版 8 帧跑步，不计当前 180 帧。逐帧字段如下：

| 字段 | 含义 |
| --- | --- |
| `texture` / `texture_size_px` | PNG 路径与实际像素尺寸 |
| `source_rect_px` | `[x,y,width,height]`，PNG 左上为原点，截取完整人物 |
| `body_bounds_px` | alpha≥8 可见轮廓的 `[左,上,右,下]`，原图坐标 |
| `pivot_px` | 相对切帧矩形左上的预览地面锚点 |
| `unity_rect_px` | 同一源矩形换算为左下原点，`y=PNG高度-源y-源高度` |
| `pivot_normalized_bottom_left` | 相对切帧矩形的归一化左下 Pivot；不是相对整张图集 |
| `source_scale_to_clip` | 通常为 1；磁核补画以此匹配原动作的绘制尺度 |
| `direction` / `phase` | 方向与动作阶段标签；阶段标签表示制作意图，仍需人工验收 |
| `contact_anchor_px` | 踢球第 5 帧估算的前伸鞋尖，相对切帧矩形左上；仅供演示 |

原图的手脚偶尔跨越等分格线，因此**不要机械等分切割图集**。索引依据真实连通透明轮廓生成，每一帧保留人物完整边界，不重画、拉伸或改写 PNG。

每个动作统一缩放：`显示主体高度 / nominal_body_height_px × source_scale_to_clip`；帧的左上落点为 `地面脚点 - pivot_px × 缩放`。禁止每帧单独适配显示高度，否则会发生身体大小跳动。PNG 路径可能随帧变化，磁核转身必须读取逐帧 `texture`。

当前 Pivot 由躯干中心和同一行的触地高度估算，能用于美术检查，尚非最终锁脚结果。鞋尖、衣摆、身形、手臂和跑步步态仍存在帧间漂移；统一脚部接触和骨架后再冻结正式 Pivot。弧光的非对称射门护具不可直接左右镜像。

播放器默认开启“行进预览”：六人沿短跑道向右前移动，速度随帧率和循环长度变化，跑道首尾淡入淡出；暂停同步停止位移。关闭后固定地面锚点，单人放大始终固定，便于分辨步态和位移。图集本身 `root_motion=false`；演示步长、跑道和速度均不是游戏移动规则，接入后需按实际速度标定脚底接触，避免滑步。帧数增加可改善衔接，最终效果仍取决于姿态和移动速度匹配。

踢球 `loop=false`，视觉击球标记为 **零基索引 4，即第 5 帧**，默认 10 fps 下为 0.4 秒。播放器可重复演示，动作后停顿再重播。球与阴影独立于角色 PNG，击球点和球的飞行只展示动作意图，未来由实际玩法模拟决定生效时刻和球的位置。

## 团结引擎资源接入

正式 `UnityProject/` 已建立。本轮按 v2 索引接入风梭、铁卫、弧光的 9 张 PNG、90 帧，位置为 `Assets/Soccer/Art/Characters/`；Editor 导入工具按逐帧矩形和 Pivot 创建 Multiple 精灵，再写入动画银行资产，保留透明通道与 `.meta`。另外三角保留在源资源目录；不要把源图完整尺寸当成角色身体尺寸。

跑步和踢球当前只完成 SE，其他方向需要继续绘制。转身图可供待机朝向检查，但不能代替八方向跑步或踢球。应先在引擎中确定相机与统一比例、修正步态和锁脚，再补方向、中间帧、持球跑、抢断、受击、庆祝及技能动作。
