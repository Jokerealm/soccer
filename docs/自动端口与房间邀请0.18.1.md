# 自动端口与房间邀请 0.18.1

## 玩家操作

启动后选择联网登录或离线进入。帐号 a / 密码 a，帐号 b / 密码 b；互联网需要登录服务，公共服务尚未部署，可先离线测试局域网。

局域网：普通模式 → 局域网 → 创建房间。只设置名字、角色和队伍，然后建房。朋友在加入页选择搜索到的房间即可。房间没有搜到时，只输入房主 IP（例如 `192.168.1.10`），程序查询房间并连接。也可以让房主点“复制邀请”，粘贴到加入页。如果同一电脑开了多个房间，用房间列表或邀请选择具体房间。

互联网直连测试：登录后创建互联网房间，填写可访问的房主 IP 或域名，可选择房间密码。建房后复制完整的 `SS1-…` 房间邀请给朋友，朋友粘贴邀请、填写密码（如有）后加入。邀请不包含帐号密码或房间密码，密码需要单独告知。

玩家无需选择、填写或复制端口。房间列表仅显示房间名称、人数和房主 IP。房间邀请只需整段复制粘贴，玩家无需了解其内容。登录服务地址也移至部署配置，启动页只显示帐号、密码与离线入口。

## 程序处理

- 创建房间优先使用 TCP 27860；被占用时由系统分配空闲端口。
- UDP 27861 用于查询和通告房间，沿用多网卡广播与组播。查询房主 IP 时同时发定向查询，并收集同一主机的房间，避免静默选错房间。
- 搜索结果与邀请携带实际 TCP 端口。邀请同时保存房间 ID 与连接方式，端口复用后旧邀请会拒绝连接，跨连接方式的邀请也会提示切换。
- 老式 `IP:端口` 地址仍供开发工具使用，玩家界面不再要求这种格式。
- 0.18.1 沿用 0.18 的比赛协议；0.18.0 可继续通过内部端点直连，新邀请需要 0.18.1 客户端。跨平台测试建议双方使用同一最新版本。

## 部署者配置

当前互联网仍是房主直连，没有公网中继。自动选择端口和房间邀请解决客户端的端口输入与同步；路由器 NAT 的公网可达性需要部署比赛服务器或中继，不能由邀请本身实现。默认端口被占用时，实际监听端口会变化，服务器侧需要相应网络策略。这个配置属于部署者，后续公共联机应由服务器统一处理。

登录服务可通过 `--soccer-auth-url https://登录域名` 配置，见 [服务说明](../server/README.md)。普通玩家无需输入服务器地址。当前没有配置服务时，点联网登录会提示选择离线进入。

移动、回血、抢球与 V/空格/鼠标操作保持 0.18.0 的规则。
