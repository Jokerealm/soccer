# 局域网与互联网联机 0.17.0

> 此页保留 0.17.0 的实现与验证记录；最新发现方式、启动登录和按键见 [0.18 更新说明](联机发现与操作优化0.18.0.md)。联机双方需要使用相同版本。

2026-10-12。新增可用的房间联机，普通模式分为“互联网”和“局域网”。两种方式共用当前 3v3 足球、武器和角色规则；排位和娱乐特殊规则仍待开发。

## 直接试玩

本机 Windows 包：`dist/SkillSoccer-0.17.0-Windows-x64.zip`。本段为 0.17.0 的历史验证说明，最新双方应使用同一版本，完整解压后运行 `SkillSoccer.exe`，无需安装引擎或 .NET。当前已发布新版 [0.17.1](https://github.com/Jokerealm/soccer/releases/tag/v0.17.1)，新增 a/a、b/b 调试帐号，详见 [最新测试步骤](调试帐号与Windows联机验证0.17.1.md)。

首页选择**普通模式 → 局域网／互联网 → 创建房间／加入房间**。每个玩家填写名字、角色和队伍，支持枪兵、雷神；房主也能加入橙队。房间共六个位置，每队三个，未占用的位置在开始时由 AI 补齐。客人点击“准备”，所有真人准备后房主点击“开始比赛”。房间里可以换角色或换到有空位的队伍，修改配置会重新取消客人的准备。

### 局域网

1. 两台电脑连接同一局域网。房主创建房间，默认房间端口 27860，可自行更改。
2. 客人进入“加入房间”，下方自动发现局域网房间，也可以点击“刷新”。点击房间的“加入”进入。
3. 自动发现受路由器隔离或防火墙影响时，可填写房主给出的 `192.168.x.x:27860` 地址直接加入。房主房间页列出本机地址，并可编辑、复制邀请地址。
4. Windows 首次提示防火墙时，允许游戏在用于联机的网络访问；局域网需要房间 TCP 端口，以及用于发现的 UDP 27861。访客 Wi-Fi 或 AP 隔离可能禁止设备互相连接，此时需使用允许设备互访的网络。

局域网房间不要求密码。

### 互联网

房主建房时可以勾选**“启用房间密码”**，输入 1—64 个字符的密码；不勾选就是无密码房间。客人填写朋友提供的公网 IP／域名和端口，需要密码时填写正确密码才能进入。密码错误、未填写密码、队伍已满、房间已满、比赛已开始、版本不一致或连接失败都有反馈。

当前实现为**公网地址直连**，不依赖 Steam 或云中继，也不提供全网房间目录。房主需要可访问的公网地址：在路由器上将所选 TCP 端口转发到运行游戏的电脑，并允许对应防火墙访问。可在建房时填写公网邀请地址，也可在房间中编辑后复制给朋友。没有公网可达地址、处于运营商 CGNAT，或网络禁止开放入站端口时，需另行提供中继／服务器方案；局域网玩法可独立使用。

密码只保存在输入框和短期握手过程中，提交后清空，不写入 PlayerPrefs、房间发现消息或日志。房主保留带随机盐的 PBKDF2-SHA256 派生校验值，使用每连接的新随机挑战和 HMAC-SHA256 验证；密码本身不在网络上传输。该原型的比赛数据使用 TCP，未提供 TLS 加密，房间密码应作为本游戏的入房口令。相关系统 API 见 [PBKDF2](https://learn.microsoft.com/dotnet/api/system.security.cryptography.rfc2898derivebytes) 和 [HMAC-SHA256](https://learn.microsoft.com/dotnet/api/system.security.cryptography.hmacsha256)。

## 比赛同步与离开

房主以 60 Hz 运行唯一比赛模拟，其他客户端只发送操作；球权、技能命中、比分、倒地和定位球由房主裁决。客户端以 20 Hz 接收完整状态和期间累计的事件，并在连续快照之间插值显示。输入编号不能指定另一个玩家的位置，重放和非法数值被拒绝。消息长度、待处理消息数、房间人数、每队人数、握手时间和失联时间均有限制。

每台电脑按自己的球员编号绑定镜头、键鼠、头顶标记、HUD、小地图、技能预览和音效。Esc 打开的是本机联机菜单，比赛继续进行；该玩家的操作暂停，其他人继续比赛。客人离开后，房主清除其未完成输入并由 AI 接管该位置；房主离开会关闭房间，客人返回加入页面并看到断线提示。比赛中暂不允许新玩家加入。

房主可从联机菜单或结算页选择“返回房间”，结束当前局或准备下一局。客人等待房主返回房间后重新准备；房主不能在客人尚未准备时启动下一局。单机训练和 AI 对练保留原来的真正暂停。

## 开发入口与验证

验证：217 项 Core 规则、22 项网络检查、44 项双进程联机检查和 320 项完整客户端回归通过；macOS／Windows 构建均 0 错误、0 警告。双进程分别验证了局域网自动发现与互联网密码房间、客人控制与踢球同步、本地菜单和离开补位；公网跨网络及两台 Windows 设备仍需实际环境试玩。汇总见 `reports/network-017-validation.json`。

- `Core/Networking/NetworkRoom.cs`：建房、加入、挑战验证、位置预留、准备与房间生命周期。
- `RoomTransport.cs`／`LanDiscovery.cs`：有界 TCP 消息与 UDP 发现，后台线程只收发消息；主线程 `Pump` 负责状态和回调。
- `NetworkCodec.cs`：固定标量格式的指令、规则和状态；完整解析验证之后再原子更新客户端状态。
- `Runtime/Application/AppNetworking.cs`：房间和比赛编排，主机模拟与客户端呈现分开。
- `Runtime/UI/NetworkUI.cs`：密码输入、建房／加入、发现列表、队伍与准备。

纯 C# 网络检查使用真实本机套接字，覆盖有密码／无密码、错误或缺失密码、挑战重放、自动发现、并发占位、满队、准备、角色、远程输入、快照、退出、重开和异常消息。运行：

```sh
tools/dotnet run --project tests/Soccer.Network.Tests -- "$PWD/reports/network-017-transport"
tools/dotnet run --project tests/Soccer.Core.Tests -- "$PWD/reports/network-017-core"
```

实际客户端检查通过 `--soccer-network-smoke` 显式启动两个进程。两个终端分别运行，端口保持一致；`internet` 检查自动创建密码房间，`lan` 检查自动发现。Windows 示例：

```powershell
.\SkillSoccer.exe --soccer-network-smoke --soccer-network-role host --soccer-network-route lan --soccer-network-port 28560 --soccer-report-dir "$PWD\SmokeHost" -logFile "$PWD\SmokeHost.log"
.\SkillSoccer.exe --soccer-network-smoke --soccer-network-role client --soccer-network-route lan --soccer-network-port 28560 --soccer-report-dir "$PWD\SmokeClient" -logFile "$PWD\SmokeClient.log"
```

执行后会自动退出，生成 `network-smoke.json` 和房间、菜单、同步踢球截图。最终汇总为 `reports/network-017-validation.json`。本机双进程验证不能替代两台 Windows 设备的防火墙、路由器广播和公网端口实测；这些环境条件需实际网络试玩复核。
