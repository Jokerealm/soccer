原生窗口补查中，Tab / Enter 能选择 AI 对练并进入角色页。自动操作工具的两次不同坐标点击，在 `Input.mousePosition` 中均读到 `(772, 138)`，UI 指针事件同样使用这一坐标；按下/松开正常收到，但鼠标位置没有同步。因此本轮未能通过该工具验证真实鼠标位置和点击，应由真人在 macOS / Windows 试玩复核。开发时可使用 `--soccer-input-probe` 和 `-logFile` 记录原始输入、UI 指针事件与命中对象，正常启动不会启用该诊断。

无图形编辑器构建可能出现环境/反射探针无法更新的一条警告；实际警告文本保存于构建 JSON 的 `warningMessages`。游戏使用默认无光照精灵，实际图形客户端另行验证。Windows 在本机只完成交叉构建，Windows 实机启动、输入、音频和性能尚未验证。

## 3. 原型假设与实现边界

- D02/D03：原型 3v3，无专属门将；人数和固定阵型还没有作为正式产品规格冻结。
- D04：采用 A，碰撞方向夹角 ≤45°；选择另一解释时须修改规则策略和用例。
- D06/D07/D09：明确脚前归属、反弹边界、侧撞保留球权并打断蓄力，均为当前配置假设。
- D10：AI 对练 300 秒＋90 秒金球加时；训练无倒计时。
- 相机与人物比例沿用 55° 轻斜俯视美术提案。逻辑尺寸不受显示压缩影响。
- 跑步/踢球仅 SE，其他方向暂用八向姿态。还有脚点漂移和滑步，尚未是正式生产动画。
- 基础球/突进采用扫掠，身体分离和护板几何仍有原型近似；移动碰撞的精确时序与多技能同刻冲突必须在联机阶段进一步验证。
- 没有联机、Steam、匹配、后端账号、排名、娱乐事件、手机触控或正式新手教学。
- 纯 C# 与输入接口为后续联机提供结构，当前未提供网络安全、跨平台确定性、预测或快照恢复保证。
