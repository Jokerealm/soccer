# 技能足球——美术资源准备

日期：2026-10-08 · 对应设计文档 v0.7 · 引擎：团结引擎 + C#

本次按用户反馈优化为「未来城市运动联赛，活泼卡通手绘，轻斜俯视的 2.5D 表现」。角色用表情、运动姿态和夸张轮廓增加趣味；人物正面与侧面、场边设施和球门厚度、统一明暗与脚底阴影共同建立体积感。

静态 v2 批次新增 **5 张 PNG 和 6 个 SVG，共 11 项资源**。初稿认可后，动画 v1 新增 19 张透明 PNG、144 帧；跑步优化 v2 再新增 **6 张 14 帧跑步图集**，当前六角各三套动作共 **180 个选用帧**。连同历史版本，共有 35 张原创 PNG、32 个原创 SVG。查看 [组合对比图库](../previews/art-gallery.html)、[动作播放器](../previews/animation-player.html)、[动画制作说明](./动画资源准备.md)、[资源索引](../assets/manifest.json) 和 [共享美术规格](../assets/art-direction-v2.json)。三角原型已选用接入风梭、铁卫、弧光的静态图和动作图集，并接入球场、SVG 派生图层和中文字体，来源见工程 `Art/provenance.json`。

## 1. 视觉与视角规范

| 项目 | v2 制作规范 |
| --- | --- |
| 主题 | 未来城市街区运动联赛，明亮、友好、富有运动感 |
| 角色 | 夸张头手和圆润运动鞋，脸部表情可见；风梭窄、铁卫宽、弧光中等 |
| 画法 | 深藏蓝描边、清晰色块、简化明暗和柔和体积高光；保持手绘 2D |
| 视角 | 轻斜俯视，能看到人物和物件的侧面；避免完全垂直俯视 |
| 预览相机 | 正交投影、无水平旋转，球场长边水平，左右球门平行；约 55° 对水平地面俯角 |
| 地面投影 | 纵向约压缩为 82%，圆形地面范围变为椭圆；人物不随地面整体压扁 |
| 体积来源 | 人物两侧明暗、鞋面、圆护具；座椅与花池侧面、围栏厚度、立体门框和独立阴影 |
| 光照 | 上左暖光，下右侧面略暗；短而柔和的接触阴影 |
| 颜色 | 藏蓝 `#132C3C`、暖白 `#F7F0E1`、青色 `#42D2C8`、琥珀 `#F4A945`、紫色 `#AD77D7` |
| 队伍识别 | 青色贴地圆环 / 琥珀贴地菱形，独立于衣服颜色；本地玩家另有头顶标记 |
| 优先级 | 足球 → 队伍与本地身份 → 技能范围 → 动作状态 → 装饰 |
| 分层 | 空场底图、地面线、球门、阴影、队伍标记、角色、足球分别保存 |

**D01 的视角方向已确认；55°、固定全场和角色显示尺寸仍是样稿参数。** SVG 与组合预览使用精确投影，生成 PNG 仅体现近似倾角，不声称完成了精确相机标定。D02/D03/D07 与最终场地尺寸仍待规则评审。

参考画布 1920×1080，48px/u，场地逻辑草案 32u×18u；地面原点约为 `(192,186.126)`。投影为 `screenX = 192 + 48x`、`screenY = 186.126 + 48 sin(55°) y`，视觉高度另向屏幕上方偏移。碰撞、踢球距离和技能范围必须在逻辑平面计算，再转换为视觉图形。生成底图与插画门框不提供碰撞或进球边界。

## 3. 预览、脚点和导入约定

图库默认使用 v2，提供新旧切换、独立地面线/球门/角色/阴影/标记开关、人物尺寸滑条及地面锚点显示。角色卡提供深底、浅底、透明网格，以及按**可见主体高度**显示的 64px/96px 缩略。

角色 PNG 保留完整原图，通过源矩形和预览脚点定位，不改写 PNG 像素。三角预览按地面 y 值排序，阴影和队伍圈固定在地面，人物向上展开。球拥有独立阴影，本地玩家标记跟随人物头顶。六人展示只是资源比例示例，不代表 D02 人数已确认。

| 角色 | alpha≥8 主体边界 `(左,上,右,下)` | 预览脚点（PNG 左上原点） | 1920px 参考画布下主体高度 |
| --- | --- | --- | --- |
| 风梭 | `(319,57,1008,1217)` | `(670,1155)` | 108px |
| 铁卫 | `(205,49,1087,1210)` | `(665,1138)` | 120px |
| 弧光 | `(309,59,1000,1227)` | `(680,1164)` | 114px |

脚点为静态预览人工估计，最终动画需依据双脚触地位置冻结。Unity 左下原点 Pivot 建议值在 `manifest.json` 中按 `(x/width,1-y/height)` 记录，不能当作已验证的绑定结果。

团结引擎导入时：PNG 设置为 Sprite (2D and UI)，保持 alpha；角色、阴影和地面标记各自使用渲染层；提交引擎生成的 `.meta`。正式缩放、Pixels Per Unit、过滤和图集间距在工程建立后按游戏比例验证，不能用完整画布大小推断角色体型。SVG 保留可编辑源，届时评估 Vector Graphics 包或导出 PNG。中文字体再创建合适的 UI 字体资源。

## 5. 复现与验证

```sh
tools/python tools/create_vector_assets.py       # 重建 v1 矢量和索引
tools/python tools/create_oblique_assets.py      # 重建 v2 投影图层
tools/python tools/build_resource_preview.py     # 重建对比图库
tools/python tools/verify_assets.py              # 检查文件、alpha、脚点、引用、许可与索引
```

PNG 保留 image_gen 原始输出，不用脚本代替图像生成或重绘。验证脚本按声明清单检查交付，不再将数量写死为第一批的 5 张 PNG。结果写入 [asset-validation.json](../reports/asset-validation.json)，透明与边界记录写入 [image-inspection.json](../reports/image-inspection.json)。
